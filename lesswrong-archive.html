The LessWrong Archive

Every post and comment on LessWrong, from the 2003 essays imported from Overcoming Bias through LessWrong 1.0 to this morning, pulled from the site's public API with every field it exposes: bodies as HTML and Markdown, karma and vote counts, reacts, tags, curation and review state, Alignment Forum flags, legacy identifiers. One zstd-compressed ndjson file per month, posts and comments together, held at the Laboratory for Social Minds, CMU, and refreshed continuously so scores and edits stay current.

CMU

The monthly files are served only to Carnegie Mellon IP ranges — on-campus networks and the CMU VPN. From anywhere else they return 403. The content is the authors' own, published on LessWrong under its terms; this copy is held for research at CMU and is not a redistribution.

The whole archiveloading…
Scores move; the archive follows. Karma, reacts, edits and deletions keep changing long after a post goes up, so the files are rewritten from the database, not appended to: the current and previous month every six hours, the last fifteen months weekly, and the whole archive once a month. The fetched_at field on each record says when its copy was taken, and the index below lists each file's SHA-256.

Reading a dump

zstd -dc LW_2012-03.jsonl.zst | head -1 | python3 -m json.tool | head -40
zstd -dc LW_2012-03.jsonl.zst | jq -c 'select(.type=="post") | {title, baseScore, voteCount, user: .user.username}'

Plain zstd -dc works; no long window is needed. Each line is one JSON object with a type of post or comment and a fetched_at timestamp, followed by the record exactly as the LessWrong API returned it. Records are ordered by postedAt, so a month reads chronologically, posts before the comments made in the same instant. Comments carry postId, parentCommentId and topLevelCommentId, so a thread rebuilds from one month's file when the post is in the same month, or from the SQLite otherwise.

Fields are present with null when they do not apply, so a reader can rely on the keys. What the API does not expose to an anonymous reader, and so is not here: individual votes (only the aggregates), drafts, private messages, and anything deleted before the 2017 migration to the current site.

Source and method

LessWrong's public GraphQL endpoint (https://www.lesswrong.com/graphql), read one request per second with an identifying User-Agent, from ganesha, by the lesswrong-pull service. Posts come from the new view and comments from allRecentComments, each walked month by month and page by page on postedAt; posts that the lists leave out but comments refer to (shortform containers, unlisted posts) are fetched by id. Everything is upserted into SQLite and a month's file is rewritten whenever any record in it changed. The site is on the same software as the EA Forum and the Alignment Forum, so the same tool would cover those.
